# Test specification — for the engine, hackathon day

For Shokhrukh. First written 10 November 2026. **Rewritten clean on the night of 11 November**, after Sherozbek's final decisions (VARIABLES.md B33 to B38). It states only what is decided now. The history is in VARIABLES.md.

**The rule of this document:** every pass mark here is written before the result exists. Do not change one after seeing a number. If a test fails, the failure goes into the output file and the write-up.

Nothing here computes a result.

---

## The method in twelve lines

1. **One shared scale per variable: min-max.** position = (value − lo) / (hi − lo), lo and hi over Earth and the target body together. Earth–Moon and Earth–Mars have their own.
2. **Whitening inside each group** (terrain, thermal, composition), from Earth's reference population. Eigenvalues floored at 0.10. No group weights.
3. **The score of an Earth cell** = its mean distance to ALL distinct cells of the target ÷ d_bar. There is no `k`.
4. **Two ranking systems are built**: every variable ranks, or only the variables Earth can match. **The main result is `all_variables`** (decided on the day, 14 November, after both had been run; section 7). The other is the second view.
5. **Ranks, not thresholds.** Each cell gets its rank among Earth's cells. The map shows the best 1% and 5%, with a slider.
6. **The chance test**: 1,000 random compact patches, same size, same |latitude|, best against best. Significant when p < 0.05.
7. **One control**: the Atacama patch. No negative control, no Apollo control.
8. **Sites** are patches of the best 1%: cells that touch are one place.
9. **Describe each site**: every variable, its gap, its verdict.
10. **Use block**: where the site succeeds, where it fails, where Earth's limits are, from the fixed table `contract/use_table.json`.
11. **Say it plainly.** A result that is not significant is printed as plainly as one that is. No adjectives.
12. Output contract **2.4**.

## 2. Unit tests — properties, not numbers

**The scale (step 3)**

1. position = (value − lo) / (hi − lo), with lo and hi from `minmax_scale_summary.json`. Loaded positions equal recomputed ones to 1e-6. Simpler and safer: load, do not recompute.
1a. **The same physical value gives the same position on both bodies.** Take a slope of 5.0°.
1b. **lo and hi do not enter any distance.** Compute one DI map from the positions and one from the raw physical values through the same calibration code. They agree to 1e-5. If they do not, something other than a straight line was applied.
2. A cell of the ranking population lies in 0..1. A clicked cell outside it (ice, water) may fall outside; print it as it is.

**Distance and DI**

3. **The score uses every distinct target cell.** DI = (mean distance to all distinct target cells) / d_bar of the set in use. Check one Earth cell by hand against a plain loop.
4. A target of ONE Earth cell, matched against an Earth sample that contains it, gives DI = 0 at that cell. A target of several cells never gives 0. **Measured on the presets, target cells only (`cube/phase4/target_spread_b36.json`): an exact copy of one target cell would score 1.8 to 4.2 for an Artemis region and 0.3 to 2.7 for a Mars zone.** So DI values for the Artemis regions will be well above 1 everywhere on Earth. That is expected. Sherozbek kept "all cells" knowing it. Always print `d_bar_target` beside `di_observed`; read DI as "like the region as a whole"; lead with ranks, not DI values.
5. DI is unchanged when the target cell list is shuffled. Duplicate target cells do not change it.
6. DI ≥ 0 everywhere. No NaN inside the complete reference population.
7. `di_combined`, computed twice from scratch, is bit-identical.
8. The combined distance is the plain distance between whitened vectors. Its square equals the sum of the per-group squared distances, to 1e-9.
9. `di_group` uses only that group's whitened columns and divides by that group's own d_bar. A cell with no composition value gets `di_group.composition = null`, not 0. `worst_group` is the largest non-null one.
10. A target with one distinct cell works: `d_bar_target = null`, `spread = 0`.
11. There is no preset, no weight argument and no `k` anywhere in the engine's interface.
12. A target near the lunar pole comes out as a compact patch of cells, not a ring. A 10 km disc at 89.5° and at 0° have cell counts within two of each other.

**The two ranking systems**

13. The system is ONE argument: `all_variables` or `earth_reachable_only`. It changes which columns enter the distance and which calibration is loaded. Nothing else.
14. **System 1 (`all_variables`).** Every variable of the parent set ranks; `ranked` is true on every row; `dims_used` is 12 for a Moon target, 13 or 11 for a Mars target.
15. **System 2 (`earth_reachable_only`).** For Haworth the ranked list is the 8 terrain variables, SiO2 and FeO. Changing a target cell's temperature changes no DI. A group with no ranked variable has `di_group` null and no raster.
16. `run.ranking.out_of_range` is the SAME list in both systems. Every variable appears in every `variables[]` row in both, with its gap and verdict.
17. Run Haworth under both. `di_terrain` is identical in the two runs.
18. The chance test of a target uses that target's ranked variables and d_bar for every random patch.

**The chance test**

19. A random patch has exactly N cells, N = the target's distinct cell count. It is the N nearest complete cells of a random centre: a compact blob.
20. Same seed → identical null. Different seed → different null.
21. Patches are drawn in the target's **absolute**-latitude band, from **both** hemispheres. Banding on signed latitude is a known bug.
22. `p = (1 + count) / (1 + B)`. Never 0, never above 1. With B = 1000 the floor prints as "p < 0.001".
23. `di_observed` on the 100,000-cell Earth sample is ≥ the minimum on the full map.
24. The null loop calls the same distance function as the real target.
25. **Record each random patch's own spread** (mean distance between its cells / d_bar) beside its minimum. Under "all cells" a uniform patch scores lower than a varied one whatever Earth looks like. Print the target's spread against the patches' spreads next to p.

**Ranks and bands**

26. `rank_combined` of a reference cell = (number of reference cells with a smaller `di_combined`) / (number of reference cells with a score). 0 is the best cell on Earth. Cells outside the reference population have no rank.
27. The best 1% holds 1% of the scored cells, to within ties (32,454 when all 3,245,417 are scored).
28. The PNG stores grey v = round(255 × sqrt(rank)); the browser reads rank = (v / 255)². Unranked cells are transparent.
29. A band is an order, never a quality. "The best 1% of Earth" exists for every target.

**Sites: patches of the best share**

Take the best X of the reference cells by rank (X = 1%, `run.site_top_share`). Cells that touch (the 8 HEALPix neighbours, `astropy_healpix.neighbours`) form one patch. Each patch is one entry: its best cell, its cell count, its area. Order by the DI of the best cell. List at most 20; write the total in `run.patches_total`.

30. Every cell of the best X% belongs to exactly one patch; no patch holds a cell outside it.
31. Same map, same X → the identical list. One broad basin gives one patch; 20 separate minima give 20.
32. Raising X never loses a cell. Patches grow or merge; none disappears.
33. `patch_area_km2` = `patch_cells` × 40.54. `rank` is 1..n with no gaps. Zero sites is a valid output.
34. The first entry is the best cell on Earth.

**Characterization and the use block**

35. `position_gap` = Earth position − target position. Zero means the same physical value. Verdict: `agrees` when |gap| < 0.10, `differs` when |gap| > 0.25, else `partial`; the boundaries are `partial`. A gap of 0.10 is one tenth of the variable's full range: 2.9° of slope, 246 m of roughness at 21 km, 27 K of temperature level, 8.6 wt% of silica (Earth–Moon; every figure is `tenth_of_scale_in_units` in `minmax_scale_summary.json`).
36. `physical_gap` is in the layer's own unit and equals `position_gap` × (hi − lo).
37. The three Mars temperature layers carry `modelled: true` in every row.
38. **The use block follows `contract/use_table.json` to the letter.** A row with an out-of-range variable goes to `beyond_earth`. Otherwise all variables agree → `succeeds`; any differs → `fails`; else not listed. If `succeeds` is empty, `general` holds the table's general sentence. The engine writes no sentence of its own.
39. Lat/lon in the output, converted back to a HEALPix index, gives the cell that was scored.

## 3. The control

**One control (Sherozbek, 11 November): the Atacama patch.** The negative controls and the Apollo control are not run.

| control | patch | centre | must return | if it does not |
|---|---|---|---|---|
| **Atacama, Yungay core** | 20 Earth cells: a centre and its 19 nearest complete cells (`contract/control_fixtures.json`, `positive_atacama`) | −24.05, −69.92; radius 14.3 km | **p < 0.05**, and expected at the floor | The test cannot see even an Earth place among Earth places. Print every p-value with the sentence "the control failed; this test has no power" beside it. |

**What it is for.** If every real target comes back "not significant", there are two explanations: Earth has no standout match, or the test is broken. The control tells them apart.

**How it is run.** The Atacama patch is used as if it were a target on the other body. Its 20 cells get their positions from their physical values like any target cell. The Earth sample must contain those 20 cells (add them if the draw missed them, and record that). The null is the ordinary one for the pairing: random compact patches on the Moon (or Mars) in the same |latitude| band, 22–26°.

**Which variables.** Under system 2 it runs on the ranking sets the preset targets use (the Atacama patch is Earth ground, so its own rule outcome would keep everything). Under system 1 it runs on the parent set; there it passes mostly because the Moon is cold, which says little. Say so.

Record `name`, `di_observed`, `p`, `passed` in `null_test.positive_control` of every output file.

## 4. Contract tests

1. Every output validates against `contract/output_schema.json`. Every click payload validates against `contract/point_schema.json`.
2. A run with zero sites, and a run with a non-significant null, both produce a complete file.
3. `contract_version` is `"2.4"`. `code_version` is a real commit hash, not `EXAMPLE-NOT-A-RESULT`.
4. `run.scale` is `"minmax"`. `run.target_cells_used` is `"all"`. `run.site_rule` is `"patches_of_top_share"`. `run.ranking.system` names the system. `dims_used` equals the length of `run.ranking.ranked_variables`.
5. `rasters[]` has `di_combined`, one `di_<group>` for each group with a ranked variable, and `rank_combined`. `run.rank_bands` is `[0.01, 0.05]`.
6. `seed`, `B`, `earth_sample_n`, `band_abs_lat`, `patch_cells`, `d_bar_earth` are the values actually used.
7. The rasters name the same `code_version` as the JSON.

## 5. Where the prototype differs — do not copy these

`build/phase4d_targets.py` and `build/phase5_null.py` are prototypes on an older design. Their results are stale.

| prototype does | now |
|---|---|
| ranks each body against itself | ONE min-max scale per variable for Earth + the target body |
| collapses the target to one median vector | mean distance to ALL distinct target cells |
| p = fraction of nulls ≤ observed | p = (1 + count) / (1 + B) |
| null patch = disc of fixed radius | N nearest complete cells of a random centre |
| null statistic = DI of the patch's median vector | **minimum** DI over the fixed 100,000-cell Earth sample |

The |latitude| banding in the prototype is right. Keep it.

## 6. Decided before any result — not open on the day

- **The scale is min-max** (B38). **Whitening is group-wise** (B34). **No weights, no presets, no weight check** (B35).
- **All target cells** (B36). `k = 5` is a number nobody could justify; "all" has no number to justify.
- **Percentile bands and the slider** (B36). No threshold on DI.
- **Sites are patches of the best 1%** (B38). The spacing rule of the spec's step 8 is not built.
- **One control, the Atacama** (B38).
- **Significance: p < 0.05.** "Significant" or "not significant", with p always printed. No "marginal".
- **A Mars target with no composition data runs without composition and says so.** It is not refused. It needs its own d_bar and its own null.
- **Wording.** The chance test is reported as it comes out. Do not rerun with other settings until p drops; that is p-hacking.
